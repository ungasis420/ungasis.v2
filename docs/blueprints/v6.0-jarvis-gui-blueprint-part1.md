# UNGASIS OS v6.0 — JARVIS GUI Blueprint (Part 1 of 2)

> Build the glassmorphism dashboard that makes UNGASIS OS *visible* — your personal JARVIS, in the browser.

## 1. Executive Summary

| Field | Value |
|---|---|
| **Goal** | Visual dashboard — health, projects, agents, wiki, automation, next actions |
| **Type** | Personal AI OS GUI; local-first MVP inside `dashboard/` |
| **Stack** | Vite 8 + React 19 + Tailwind CSS 4 + Zustand 5 + Framer Motion 12 |
| **Design** | Dark glassmorphism (#0a0a1a base, #00d4ff accent, glass surfaces) |
| **Sprints** | 4 waves (~8 sessions, ~2 weeks) |
| **Budget** | $0 new spend — uses existing Google AI Pro + Claude Pro + company tools |
| **Data Source** | Python scripts → JSON cache → React reads JSON (no backend for MVP) |
| **Entry Point** | `dashboard/dist/index.html` (open in browser, like Newmont) |
| **Truth** | CLAUDE.md remains canonical; GUI reads script outputs only |

## 8. Startup Sequence Design

### 8A. Full Lifecycle Timeline

| Moment | Trigger | What Runs | Result |
|---|---|---|---|
| **PC boot** | PowerShell profile | `startup-sequence.ps1` → 5 scripts | JSON cache warmed in `.ungasis/dashboard/` |
| **Dashboard opens** | Browser load | React `useEffect` reads JSON files | Cards fill with data, greeting shows |
| **Session start** | User clicks "Start Session" | `wiki-inject.py` + `session-recovery.py` | Hot context + recovery prompt ready |
| **Session end** | User clicks "End Session" | `token-logger.py` + CONTEXT.md update | Token log saved, next-step suggestion |
| **Overnight** | Windows Task Scheduler | `scheduled-tasks.ps1` (v5.4) | Backup ZIP, wiki-lint, research digest |
| **Laptop close** | User action | State already saved | Ready for tomorrow |

### 8B. Boot-to-Dashboard Flow

```
PC ON → PowerShell profile loads
  └─► startup-sequence.ps1
        ├─► python scripts/ungasis.py pulse --json    → health.json
        ├─► python scripts/session-recovery.py --json → session.json
        ├─► python scripts/wiki-lint.py --json        → wiki-health.json
        ├─► python scripts/token-report.py --json     → tokens.json
        └─► python scripts/cross-project.py --json    → lessons.json

User opens browser → dashboard/dist/index.html
  └─► React app loads
        ├─► Reads .ungasis/dashboard/*.json (5 files)
        ├─► Populates 7 Zustand stores
        ├─► Renders Greeting (time-aware)
        ├─► Staggered card fade-in (0.1s delay each)
        └─► Auto-refresh poll starts (every 60s, reads JSON)

Mel closes laptop → scheduled tasks continue overnight
```

### 8C. startup-sequence.ps1 Spec

| Step | Command | Output File |
|---|---|---|
| 1 | `python scripts/ungasis.py pulse --json` | `.ungasis/dashboard/health.json` |
| 2 | `python scripts/session-recovery.py --json` | `.ungasis/dashboard/session.json` |
| 3 | `python scripts/wiki-lint.py --json` | `.ungasis/dashboard/wiki-health.json` |
| 4 | `python scripts/token-report.py --json` | `.ungasis/dashboard/tokens.json` |
| 5 | `python scripts/cross-project.py --json` | `.ungasis/dashboard/lessons.json` |

**Change needed:** Each existing script gets a `--json` flag → writes JSON to `.ungasis/dashboard/` instead of printing to terminal. Default behavior stays the same.

### 8D. Greeting Logic

| Time Range | Message |
|---|---|
| 05:00–11:59 | "Good morning, Mel. Here's your day." |
| 12:00–17:59 | "Good afternoon, Mel. Here's your progress." |
| 18:00–04:59 | "Good evening, Mel. Here's where you left off." |

### 8E. Startup Rules

| Rule | Why |
|---|---|
| Do not block UI on slow scripts | Show skeleton/loading state first, fill cards when JSON ready |
| Cache outputs as JSON | Faster load, easier parsing, works offline |
| Manual refresh stays | Mel stays in control — auto-poll is optional |
| Plain English errors | ESL-friendly — no stack traces in UI |
| No secrets displayed | Safe for screen sharing — summaries only, never keys |
| Stale data indicator | Show "Last refreshed: 3 hours ago" badge if data > 1 hour old |

## 9. Data Layer

### 9A. Decision

| Option | Decision | Why |
|---|---|---|
| Browser subprocess | ❌ Avoid | Browser cannot safely run local commands |
| REST API (Flask) | ❌ Overbuilt | New dependency, not needed for MVP |
| **JSON file reads** | **✅ Wave 1–3** | Scripts write JSON, React reads at build-time or via fetch. Free, simple. |
| **Node bridge** | **✅ Wave 4** | Tiny Express server for live refresh. Only when needed. |

**MVP pattern (Wave 1–3):** Like Newmont — scripts write JSON → build-time import → baked into dist.
**Live pattern (Wave 4):** Optional Node bridge reads JSON, serves via localhost API.

## 13. Risks + Mitigations

| # | Risk | Impact | Likelihood | Mitigation |
|---|---|---|---|---|
| R1 | Browser cannot run Python directly | High | Certain | JSON cache (W1–3) + Node bridge (W4) |
| R2 | Scope creep — add features too early | High | High | Stick to sprint plan. No Persona Factory until v6.1 |
| R3 | Script `--json` flag breaks existing behavior | Medium | Low | Add as *optional* flag — default unchanged |
| R4 | Recharts bundle too large | Medium | Medium | Lazy-load chart page. Tree-shake unused. |
| R5 | Agy writes to scratch dir, not project | High | High | Use `--add-dir`. Run `merge-agy-output.ps1` after |
| R6 | File boundary conflict (both agents edit same file) | High | Medium | Follow §11 boundary table strictly |
| R7 | Script output format varies / changes | Medium | Medium | Normalize via `parse-script-output.ts` adapter |
| R8 | Privacy leak — secrets shown in UI | High | Low | Summaries only. No .env reads. No key display. |
| R9 | Over-automation — dashboard does too much | Medium | Medium | Keep manual refresh + approval gates. MVP first. |
