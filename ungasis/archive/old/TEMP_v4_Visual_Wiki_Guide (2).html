  • The 12 layers of token efficiency — from codebase architecture to context engineering

Context Engineering — The New Discipline

NEW in v4.0 The industry shift from prompt engineering to context engineering.

Prompt Engineering vs Context Engineering

Prompt engineering asks: "How do I phrase this request?"

Context engineering asks: "What does the agent need to know to succeed, and what can I strip out?"

Anthropic formalized this in September 2025: "Context engineering is the set of strategies for curating and maintaining the optimal set of tokens during LLM inference."

A perfect prompt inside a bloated context window still produces mediocre output. A mediocre prompt inside a surgically curated context often produces great output.

Feynman Explanation: Prompt engineering is choosing the right words for your question. Context engineering is choosing which room to have the conversation in, which documents to put on the table, and which distractions to remove — before you open your mouth.

Why This Matters for Coding Agents

Chat is one-shot. Agents run in loops — 10, 20, 50+ tool calls per task. Each loop adds data. Without active curation, context degrades every turn. This is called context rot.

DisciplineFocusWhen It Matters
Prompt EngineeringHow you write the instructionSingle-turn Q&A, chat
Context EngineeringWhat the model sees at each turnMulti-turn agents, long sessions, tools

Every layer in this guide (1–12) is a context engineering decision.

The Problem — Why Tokens Matter

Understanding the one thing that changes everything about AI coding.

What Is a Token?

A token is a small piece of text — about ¾ of a word. When you talk to an AI tool, everything is measured in tokens: your message, its reply, and every previous message.

Feynman Explanation: Imagine you're writing on a whiteboard that has a fixed size. Every time you write something new, you also have to re-write everything before. Eventually you run out of space and start erasing — the AI "forgets" your earlier instructions.

The Context Window Problem

Every AI model has a fixed "memory size." Think of it like a glass of water — it can only hold so much.

Like a restaurant kitchen. Imagine a chef who must re-cook every dish before making a new one. By dinner, they spend 90% of time re-cooking. That's what happens in long AI conversations.

The Auto-Compaction Trap CRITICAL

When your AI's memory gets ~93% full, it auto-compresses. This sounds helpful, but:

  • ❌ Each compression costs 100,000–200,000 tokens
  • ❌ It can happen 3–4 times in a long session
  • ❌ Important details often get lost
  • ✅ Solution: Compact manually at 60–70%

The 1M Token Wall CRITICAL

Even with 2M token windows, performance drops after ~1M tokens. Bigger memory doesn't solve it — cleaner memory does.

Like a messy desk. A bigger desk doesn't help if it's covered in papers. What helps is keeping only the papers you need right now.

Context Rot NEW in v4.0

Context rot (Chroma 2025, Fundesk 2026) is what happens when context fills with stale file reads, old tool outputs, and resolved discussions. Every frontier model degrades as context fills — even if the window isn't "full."

Meta Research (May 2026) found that a two-line structured failure summary outperforms thousands of tokens of raw logs when guiding an agent's next attempt.

Feynman Explanation: Context rot is like a junk drawer. Not full — but so cluttered that finding the scissors takes longer than if the drawer had fewer things.

Pre-Tool Hooks — Output Filtering NEW in v4.0

What it does: Filters command/tool output before it enters context. Truncates logs, retains only relevant lines.

Savings: 80,000 → 20,000 tokens (75% reduction) on command outputs.

How: Pipe only relevant slices instead of whole files:

# Bad: pass entire file
claude -p "Improve formatDate in utils.ts"

# Good: extract just the function
sed -n '/^export function formatDate/,/^}/p' utils.ts | claude -p "Improve this"

# Good: pass only last 100 lines of log
tail -n 100 production.log | claude -p "Find the error"

Source: Blockchain Council & ClaudeCodeLab (Apr 2026). Tool outputs are 30–45% of all tokens. Filtering at source is highest-ROI.

Step-by-Step Setup Guide

Follow these steps for any new project. Do it once, works forever.

Feynman Explanation: Setting up TEMP is like setting the GPS before a road trip. You spend 5 minutes at the start, but you save hours of wrong turns during the drive.

1

📁 Organize Your Code First

Keep files small (under 300 lines), use clear names, avoid deep nesting. This saves more tokens than any tool or setting.

2

📄 Create Your Instruction Files

Unzip TEMP v4.0 into your project root. Replace [PROJECT_NAME] and [TECH_STACK] with real values. Delete files for tools you don't use. Create .claudeignore.

your-project/
├── AGENTS.md              ← Universal (any tool)
├── CLAUDE.md              ← Claude Code
├── .claudeignore          ← Index exclusion (NEW)
├── .clinerules            ← Cline
├── .cursorrules           ← Cursor
├── GEMINI.md              ← Gemini / Jules
├── .github/
│   └── copilot-instructions.md
└── docs/
    ├── PROJECT_BRIEF.md
    ├── PROJECT_MEMORY.md
    ├── TEST_COMMANDS.md
    ├── TASK_HANDOFF.md
    ├── SESSION_SUMMARY.md
    └── DECISIONS.md
3

🔧 Install Free Token-Saving Tools

Pick the tools that match your project size:

# Knowledge graph (large projects):
pip install graphifyy
# Context packing:
npx repomix --compress
# Cline memory:
Ask Cline: "initialize memory bank"
4

⚙️ Set Your Session Rules

During every work session:

  • ✅ Cap at 15–20 messages, then start fresh with handoff
  • ✅ Compact at 60–70% context (don't wait for auto-compaction)
  • ✅ Plan before coding for multi-file changes
  • ✅ Give the AI tests or expected output to verify itself
  • ✅ Use pre-tool hooks / pipe technique for large files
5

📋 End-of-Session Ritual

After each session, update: TASK_HANDOFF.md, SESSION_SUMMARY.md, PROJECT_MEMORY.md. If architecture decisions changed, update DECISIONS.md. If the agent hit a trap, update GOTCHAS.md.

6

📊 Track and Improve

Monthly review: Are instruction files current? Am I hitting rate limits? Am I using the right model tier for each task type? Are any always-on instructions better as on-demand skills?

Best Case Usage Scenarios

Real-world situations where TEMP v4.0 saves the most.

Scenario 1: Long debugging session. Fixing a bug across 5 files. Without TEMP, the AI re-reads all 5 files every turn. With TEMP: AI shows only changed lines, uses subagents for parallel investigation, hands off cleanly. Savings: ~70–90%.

Scenario 2: New project kickoff. Setting up a React + Tailwind project. Without TEMP, you re-explain your stack every session. With TEMP: CLAUDE.md loads automatically, AI knows your stack from message 1. Savings: ~15–20 min per session, ~64% fewer instruction tokens.

Scenario 3: Multi-day feature build. Building a dashboard over 5 days. Without TEMP, each session starts from zero. With TEMP: Memory Bank / TASK_HANDOFF.md carries context forward. Savings: ~80% context setup time.

Scenario 4: Large codebase navigation. You ask "how does auth work?" in a 50-file project. Without TEMP, it reads 50 files (285K tokens). With TEMP + Graphify: It reads the knowledge graph. Savings: 7x–49x tokens.

Scenario 5: Team collaboration. Three developers share a project. Without TEMP, each person's AI has different conventions. With TEMP: AGENTS.md + instruction files are version-controlled. Everyone's AI follows the same rules.

Scenario 6: MCP-heavy workflow. NEW You have 15 MCP servers connected but only use 3 for the current task. Without TEMP, all 15 tool schemas load every turn (thousands of wasted tokens). With TEMP v4.0: Prune unused MCP tools, use pre-tool hooks to filter outputs. Savings: up to 98% on MCP payload tokens.
