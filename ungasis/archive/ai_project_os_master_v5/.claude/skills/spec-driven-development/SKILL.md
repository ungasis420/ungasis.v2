# Spec-Driven Development Skill

Use for new features, multi-file changes, ambiguous tasks, automations, integrations, or user-facing behavior.

## Process

1. Interview for goal, user, constraints, edge cases, and success criteria.
2. Write requirements in `specs/<feature>/requirements.md`.
3. Write design in `specs/<feature>/design.md`.
4. Break work into small tasks in `specs/<feature>/tasks.md`.
5. Define acceptance in `specs/<feature>/acceptance.md`.
6. Implement one task at a time after approval when needed.
7. Update specs when implementation changes the plan.

## Output

```text
Spec folder:
Requirements summary:
Design summary:
Task list:
Acceptance checks:
Human review gate:
Next implementation task:
```
