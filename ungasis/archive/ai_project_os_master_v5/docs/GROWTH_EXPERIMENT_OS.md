# Growth Experiment OS

Purpose: use the same AI project operating system for growth, content, sales, learning, research, and business experiments - not only coding.

## Core idea

Claude Code-style workflows are useful beyond code when the work can be represented as files, checks, and repeatable loops.

```text
Hypothesis -> asset/spec -> execution plan -> small experiment -> metric -> review -> next iteration
```

## Use this for

- landing pages
- content systems
- sales scripts
- onboarding flows
- SEO/content briefs
- lead magnet experiments
- customer research
- lifecycle email drafts
- product positioning
- growth dashboards
- internal operating routines

## Growth experiment file set

| File | Purpose |
|---|---|
| `templates/growth_experiment.md` | One experiment packet |
| `docs/WORKLOG.md` | What happened |
| `docs/LESSONS_LEARNED.md` | Reusable learning |
| `context/user-profile.md` | Audience and user assumptions |
| `docs/QUALITY_BAR.md` | What counts as good |
| `docs/EVAL_PLAN.md` | Metrics and checks |

## Growth loop

1. Define one hypothesis.
2. Define target audience and promise.
3. Create one asset or action.
4. Define the metric and pass/fail threshold.
5. Run manually or with approved automation.
6. Review evidence.
7. Keep, kill, or iterate.
8. Save the lesson.

## Safety rules

- Do not fabricate proof, testimonials, logos, metrics, or customer claims.
- Do not scrape private or restricted data.
- Do not spam, impersonate, or automate outbound messages without review.
- Get approval before posting publicly, emailing users, changing live pages, spending money, or touching customer data.
