# Community Safety Rules Checklist

- [ ] Think Before Coding: goal, assumptions, and success criteria are clear.
- [ ] Simplicity First: no speculative abstractions or unnecessary files.
- [ ] Surgical Changes: every change traces to the request.
- [ ] Goal-Driven Execution: verification evidence exists.
- [ ] Token Budget Rule: task is narrow and context is curated.
- [ ] Checkpoint Rule: pause after about three meaningful changes.
- [ ] Read-Before-Write Rule: relevant files were inspected before editing.
- [ ] Fail-Loud Rule: blockers/failures are stated plainly.
