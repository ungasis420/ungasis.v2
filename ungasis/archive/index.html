📍 Dashboard / 10-Phase Workflow

⚡ 10-Phase Workflow

From idea to revenue in 30 days. Click to expand.

🛑 STOP gates: Phase 2 → if <70% confirm, new idea. Phase 6 → if users don't return, pivot.
Phase 1: 💡 Pick Idea Days 1–2▶
  • Write 3 ideas
  • Score Pain × Frequency × WTP
  • Check Google Trends + Reddit/X
  • Pick ONE idea

Tools: Notion + ChatGPT

Phase 2: 🔍 Validate Pain Days 3–5▶
  • Write problem statement
  • Find 10 people
  • Create 5Q survey
  • Get 15+ responses
  • ≥70% confirm → GO

Tools: Tally.so + Reddit

Phase 3: 🎨 Design MVP Days 6–7▶
  • List 3 core screens
  • Sketch wireframes
  • Define ONE user flow
  • Write NOT-building list

Tools: Excalidraw + Figma

Phase 4: 🖱️ Build Prototype Days 8–10▶
  • Describe app in Bolt.new
  • Iterate 3–5×
  • Add sample data
  • Deploy + share with 5 people

Tools: Bolt.new or Lovable

Phase 5: 🔧 Build Real MVP Days 11–20▶
  • Create Next.js project
  • Set up Supabase (tables+auth+RLS)
  • Build screens with Cline
  • Connect to DB
  • Test all flows

Tools: VS Code + Cline

Phase 6: 🧪 Test with Users Days 21–23▶
  • Invite 10–20 testers
  • Screen share / Loom
  • Collect feedback (Tally)
  • Fix top 3 bugs
  • Decide: persist / pivot / kill

Tools: Tally + Loom

Phase 7: 🚀 Deploy Days 24–25▶
  • Push GitHub → Cloudflare Pages
  • Custom domain (~$10/yr)
  • Add PostHog/Umami
  • Announce publicly

Tools: Cloudflare + PostHog

Phase 8: 💰 Monetize Days 26–28▶
  • Choose model (one-time / sub / freemium)
  • Set up Lemon Squeezy
  • Create product
  • Add checkout button
  • Test mode first!

Tools: Lemon Squeezy

Phase 9: 📈 Track Metrics Day 29▶
  • Visitors → signups (>10%)
  • Active users (>30% return)
  • Paying users (>2%)
  • Churn (<5%/mo)

Tools: PostHog + Supabase

Phase 10: 🔄 Improve & Scale Day 30+▶
  • Review weekly
  • 1 feature per 2-week sprint
  • Upgrade Supabase @400MB
  • Consider Stripe @$5K/mo

Tools: VS Code + analytics

📝 Copy-Paste Prompt Library

8 ready-to-use prompts. Click Copy to grab, paste into ChatGPT / Copilot / Cline.

1. 💡 Idea Validation

Act as a startup product strategist and beginner teacher. My app idea: [DESCRIBE IDEA] Target user: [WHO HAS THE PROBLEM] Current workaround: [HOW THEY SOLVE IT TODAY] Help me validate before building. Output: 1. One-sentence Product North Star 2. Pain × Frequency × WTP score (1-5 each) 3. Top 5 assumptions that may be wrong 4. 10 customer interview questions 5. 7 Tally survey questions 6. Pass/fail validation threshold 7. MVP features: exactly 3 8. NOT-building list: at least 5 items 9. Best next action today Use simple English. Do not encourage building before proving pain.

2. 🎨 UX Design

Act as a senior UX designer for beginner-friendly mobile-first apps. Product North Star: [ONE SENTENCE] Target user: [USER] Main workflow: [USER DOES A → B → C → GETS RESULT] Design the simple MVP experience. Output: 1. User journey (step by step) 2. Screen list (max 5 screens) 3. What each screen shows 4. Main button on each screen 5. Empty / loading / error / success states 6. Simple design system (colors, font, components) 7. Mobile-first notes 8. Accessibility basics 9. What NOT to design yet Use simple English.

3. 🤖 AI App Builder (Bolt/Lovable)

Build a beginner-friendly web app prototype. App name: [NAME] Purpose: [PRODUCT NORTH STAR] Target user: [USER] MVP scope: [3 FEATURES ONLY] Screens: 1. Landing / welcome 2. Dashboard 3. Main action 4. Result / detail 5. Settings (if needed) Data model: [LIST ENTITIES AND FIELDS] Design: Clean, mobile-first, modern, trustworthy. Include empty, loading, error, and success states. Rules: - Use fake/demo data only - No real API keys - Keep provider logic isolated - Add README with run instructions - Make it easy to export to GitHub After building, explain: 1. File structure 2. How to run 3. Where data is stored 4. What to test 5. Known limitations

4. 🔧 Cline / AI Coding Safe Task

Act as a careful senior developer. Project: [APP NAME] Goal for this task: [ONE SMALL CHANGE] Relevant files: [LIST FILES IF KNOWN] Rules: - Make the smallest safe change - Do NOT rewrite unrelated files - Do NOT touch secrets or .env files - Before editing, say which files you plan to modify - After editing, summarize changed files - Give exact test steps - Include rollback advice Task: [DESCRIBE CHANGE]

5. 🐛 Debugging

Act as a patient senior full-stack developer. App stack: [TOOLS] Expected behavior: [WHAT SHOULD HAPPEN] Actual behavior: [WHAT HAPPENS INSTEAD] Error message: [PASTE EXACT ERROR] Recent changes: [WHAT CHANGED BEFORE IT BROKE] Please: 1. Explain likely cause in simple English 2. Give the safest first fix 3. Show exact lines/files to check 4. Give test steps after fix 5. Give rollback plan 6. Tell me what NOT to change yet Do not rewrite everything unless necessary.

6. 🚀 Launch Checklist

Act as a strict but practical launch reviewer. App: [APP NAME] Target user: [USER] Current stage: [PRIVATE BETA / PUBLIC MVP / MONETIZED] Stack: [TOOLS] Review launch readiness. Output: 1. Readiness score /100 2. Blockers (must fix before launch) 3. Nice-to-fix later 4. Privacy/security checklist 5. Payment checklist (if monetized) 6. Analytics checklist 7. Support checklist 8. Backup/export checklist 9. First 7 days after launch plan Use simple English and be direct.

7. 🔍 Source Verification

Act as a source-first research checker. Claims to verify: [PASTE CLAIMS] Verify using official sources first. Output: | Claim | Official Source | Verified? | Confidence | Notes | Action | Rules: - Do NOT invent citations - If not verified, say "unverified" - Separate facts from assumptions - Use current sources only

8. 🤝 Session Handoff

Create a handoff summary for my next AI session. Include: 1. Project name 2. Current goal 3. Current stage 4. Stack/tools used 5. Decisions made this session 6. Files created or changed 7. Known bugs 8. Next 3 actions 9. Safety notes 10. Prompt to continue next session Keep it compact and beginner-friendly.
📍 Dashboard / SOPs & Checklists

📋 SOPs & Checklists

Standard Operating Procedures — follow these every time.

SOP 1: 🆕 Start a New Project▶
  1. Write Product North Star (1 sentence)
  2. Create Notion/Markdown project page
  3. Create validation form (Tally.so)
  4. Create GitHub repo (if code involved)
  5. Add README + PROJECT_WORKFLOW.md + .env.example
  6. Build smallest prototype
  7. Test one core workflow
  8. Record next 3 tasks

Done when: project has clear goal, safe storage, and one next action.

SOP 2: 🔍 Review AI-Generated Code▶
  1. Read changed files list
  2. Check NO secrets were added
  3. Run app locally
  4. Test main workflow
  5. Check mobile layout
  6. Commit ONLY if working
  7. Write what changed in CHANGELOG

Done when: app runs and rollback exists.

SOP 3: 🧪 Prepare Private Beta▶
  1. Use dummy/demo data only
  2. Create feedback form (Tally)
  3. Add contact/support method
  4. Test main flow end-to-end
  5. Add basic monitoring if public link
  6. Invite 3–10 testers
  7. Track feedback weekly

Done when: testers can use the app safely.

SOP 4: 💰 Monetization Readiness▶
  1. Validate pain with real users first
  2. Confirm repeated usage or willingness to pay
  3. Define offer and price hypothesis
  4. Choose payment method (Lemon Squeezy / PayMongo)
  5. Add refund/support policy
  6. Check privacy/tax/legal requirements
  7. Test payment flow in TEST mode first

Done when: payment is tied to validated value, not guessing.

SOP 5: 🚨 Emergency — Leaked Secret▶
⚠️ If it was committed to Git, assume it was exposed. Just deleting the file is NOT enough.
  1. STOP using the exposed key immediately
  2. Revoke/rotate in the provider dashboard
  3. Remove from code + check Git history
  4. Check hosting environment variables
  5. Create a NEW key
  6. Store safely in env variables only
  7. Document what happened in DECISIONS.md

🚨 Kill Switch Triggers

Stop ALL agents immediately if any of these happen:

  • Production data touched without approval
  • Cost exceeds $10 in one session
  • Unauthorized API call
  • Cascading failures (3+ agents failing)
  • Agent tries to merge without human approval

🔑 API Key Policy

❌ NEVER Do This

  • Put API key inside a React component
  • Paste API key into ChatGPT or any AI chat
  • Commit .env.local to GitHub
  • Screenshot a dashboard showing keys
  • Store service_role key in NEXT_PUBLIC_ variable

✅ Safer Pattern

WhereWhat Goes Here
.env.localReal secrets — YOUR machine only
.env.exampleFake placeholder names — in GitHub
Hosting secretsEnvironment variables in Netlify/Cloudflare
Server-side codeUses secrets (API routes, edge functions)
Frontend codeNEVER sees private secrets
💡 Supabase note: The anon key is designed for client use WITH Row Level Security. The service_role key is powerful and must stay server-side only.

✋ Human Approval Gates

Require human approval BEFORE automation does any of these:

  • Sends messages to real users
  • Deletes records or production data
  • Updates permissions
  • Submits forms on behalf of users
  • Publishes content publicly
  • Charges money
  • Refunds money
  • Contacts customers
  • Changes legal/tax/security state
