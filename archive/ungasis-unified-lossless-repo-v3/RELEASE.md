# Release Guide

A release means sharing a version for use.

## Before release

- [ ] Local checks pass.
- [ ] CI checks pass on GitHub.
- [ ] No secrets are in the repo.
- [ ] Permission matrix is reviewed.
- [ ] Human approval gates are reviewed.
- [ ] Rollback plan is written.
- [ ] Version number is chosen.
- [ ] Change log is updated.

## Release steps

1. Create a version tag, like `v1.0.0`.
2. Save the ZIP artifact.
3. Write release notes.
4. Keep the previous version available for rollback.
