# Simple Glossary With Feynman Explanations

Each word has two parts:

- **Feynman:** simple explanation.
- **Layman analogy:** everyday comparison.

## Repository

**Feynman:** a repository is a project folder that stores files and history.  
**Layman analogy:** a binder for one project.

## Production

**Feynman:** production means real people can use it safely.  
**Layman analogy:** a restaurant kitchen open to customers, not just family cooking.

## Production ready

**Feynman:** production ready means the system is tested, safe enough, documented, monitored, and can be fixed if something breaks.  
**Layman analogy:** a car passed inspection before driving on a highway.

## CI

**Feynman:** CI means automatic checks run when files change.  
**Layman analogy:** a robot teacher checking homework before submission.

## Schema

**Feynman:** a schema is a rule that says what a config file must contain.  
**Layman analogy:** a form that rejects missing name, date, or signature.

## Config

**Feynman:** config is a settings file.  
**Layman analogy:** the knobs on a washing machine.

## Secret

**Feynman:** a secret is private information like an API key, password, token, or connection string.  
**Layman analogy:** a house key.

## API key

**Feynman:** an API key lets software use another service.  
**Layman analogy:** a membership card that opens a service desk.

## Token

**Feynman:** a token is a temporary or reusable pass for access.  
**Layman analogy:** a hotel key card.

## Permission

**Feynman:** permission says what someone or something is allowed to do.  
**Layman analogy:** visitor badge, staff badge, or manager badge.

## Least privilege

**Feynman:** give only the minimum permission needed.  
**Layman analogy:** a delivery person gets the lobby code, not the safe code.

## Human approval gate

**Feynman:** risky actions wait for a person to approve.  
**Layman analogy:** a bank asks for confirmation before sending money.

## Agent

**Feynman:** an agent is an AI helper with a role and possible tools.  
**Layman analogy:** an assistant assigned to one job.

## Orchestration

**Feynman:** orchestration coordinates many steps, people, tools, or agents.  
**Layman analogy:** a conductor guiding an orchestra.

## Runtime

**Feynman:** runtime is the part that actually runs the workflow.  
**Layman analogy:** a recipe is not dinner; the runtime is the cooking.

## Observability

**Feynman:** observability helps you see what happened when something worked or failed.  
**Layman analogy:** CCTV, receipt, and clock together.

## Log

**Feynman:** a log is a record of what happened.  
**Layman analogy:** a diary for software.

## Run ID

**Feynman:** a run ID is a unique name for one execution.  
**Layman analogy:** an order number on a receipt.

## Rollback

**Feynman:** rollback means going back to the last safe version.  
**Layman analogy:** undo button.

## Release

**Feynman:** a release is a version you share or deploy.  
**Layman analogy:** publishing a new edition of a book.

## Red-team test

**Feynman:** a red-team test tries to break the system safely to find weak spots.  
**Layman analogy:** a friend tries your lock before a thief does.

## Smoke test

**Feynman:** a smoke test is a quick basic test to see if the system is alive.  
**Layman analogy:** turning on a light to see if power works.

## Supply chain

**Feynman:** supply chain is all outside tools, code, actions, and packages your project depends on.  
**Layman analogy:** ingredients used to cook a meal.

## SBOM

**Feynman:** SBOM means a list of software ingredients.  
**Layman analogy:** a nutrition label for code.

## Prompt injection

**Feynman:** prompt injection is when bad text tricks AI into ignoring rules.  
**Layman analogy:** a fake note telling a guard to open the door.

## Excessive agency

**Feynman:** excessive agency means AI can do too much without enough control.  
**Layman analogy:** giving a trainee the keys to the whole building.

## Placeholder

**Feynman:** a placeholder is a blank or sample value waiting to be replaced.  
**Layman analogy:** “Dear [NAME]” in a letter.

## GitHub Actions

**Feynman:** GitHub Actions runs checks automatically when project files change.  
**Layman analogy:** a robot assistant checks your work when you submit it.

## Workflow

**Feynman:** a workflow is a list of automatic steps.  
**Layman analogy:** a recipe with steps.

## YAML

**Feynman:** YAML is a simple text format for settings.  
**Layman analogy:** a grocery list with indented sub-lists.

## JSON

**Feynman:** JSON is a strict text format for structured data.  
**Layman analogy:** labeled boxes inside bigger boxes.

## Script

**Feynman:** a script is a small file of instructions a computer can run.  
**Layman analogy:** a checklist the computer follows.

## Commit

**Feynman:** a commit saves a project change in history.  
**Layman analogy:** a photo of your project at one moment.

## Branch

**Feynman:** a branch is a separate line of work.  
**Layman analogy:** a draft copy before changing the final document.

## Pull request

**Feynman:** a pull request asks someone to review and accept changes.  
**Layman analogy:** asking a teacher to check your edited paper.

## CODEOWNERS

**Feynman:** CODEOWNERS says who must review important files.  
**Layman analogy:** a manager sign-off list.

## Environment variable

**Feynman:** an environment variable is a setting stored outside the code.  
**Layman analogy:** a sticky note kept in a private drawer, not printed in the manual.

## Artifact

**Feynman:** an artifact is a file produced by a process.  
**Layman analogy:** a finished report from a printer.

## Dependency

**Feynman:** a dependency is outside code or a tool your project needs.  
**Layman analogy:** a recipe needing flour from a store.

## Staging

**Feynman:** staging is a test area before real production.  
**Layman analogy:** a dress rehearsal before the show.

## Deployment

**Feynman:** deployment puts the project where users can use it.  
**Layman analogy:** opening the shop doors.

## Monitoring

**Feynman:** monitoring watches if the system is healthy.  
**Layman analogy:** a dashboard in a car.

## Trace

**Feynman:** a trace follows the path of one action through the system.  
**Layman analogy:** tracking a delivery package.

## Metric

**Feynman:** a metric is a number used to judge performance.  
**Layman analogy:** a score on a scoreboard.

## Risk

**Feynman:** risk means what could go wrong and how bad it could be.  
**Layman analogy:** checking weather before a trip.

## Production candidate

**Feynman:** production candidate means it may be close, but final approval is still needed.  
**Layman analogy:** a student ready for final exam, not graduated yet.
