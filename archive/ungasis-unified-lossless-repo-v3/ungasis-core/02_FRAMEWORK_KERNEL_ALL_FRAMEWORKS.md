## Framework: Good Prompt Formula
**ID:** FRM-001

**Use when:** Any prompt review or rebuilt prompt.

**Main idea:** Clear Job + Background + Rules + Output Shape + Quality Check.

**Beginner explanation:** A prompt is like ordering food. The clearer the order, the better the result.

**Process:** Ask: What do you want? What context matters? What rules apply? What should the answer look like? How should it check itself?

**Tiny example:** Weak: Help me study. Strong: Make a 7-day beginner biology study plan with quizzes.

**Failure modes:** Overusing the framework, applying it at the wrong rigor level, or confusing method with final answer.

**Best paired engines:** Prompt Architect, R&D, App Builder, Workflow, Business, QA, or Culinary engines depending on task.

**Safety / ethics notes:** Use the framework to improve clarity and safety, not to rationalize harmful actions.

# UNGASIS v5 Update — Universal Gold Skeleton + Design Excellence

This v5 update deepens app-building behavior without making Project/GPT instructions longer.

Core upgrade:
- Every app build should use the **Universal Gold Skeleton Key**.
- Every app build should include the **Design Excellence Layer**.
- Rigor Dial decides whether each layer is **Active**, **Stub**, **Blueprint**, or **Deferred**.
- Personal prototypes stay lightweight, but still receive a global-quality foundation.
- Public/commercial/high-risk apps receive full QA, security, legal, privacy, compliance, monitoring, and launch rigor.


# Framework: Universal Gold Skeleton Key

## Framework ID
FW-APP-GOLD-001

## Main Idea
Every app gets a complete architectural map, but Rigor Dial decides which parts are built now.

## Process
1. Classify stage: personal, prototype, private beta, public, commercial, high-risk.
2. List all Gold Skeleton layers.
3. Assign each layer Active / Stub / Blueprint / Deferred.
4. Build only the active layers.
5. Add stubs for near-term layers.
6. Document blueprint layers.
7. Defer everything else.
8. Create acceptance tests before building.

## Failure Modes
- Building too much too early
- Building a beautiful UI with no data architecture
- Building backend before UX is clear
- Skipping analytics and not knowing what works
- Adding AI APIs before the core workflow is useful

# Framework: Design Excellence Framework

## Framework ID
FW-DESIGN-EXCELLENCE-001

## Main Idea
Design quality is not decoration. It is usability, trust, clarity, responsiveness, accessibility, and emotional fit.

## Process
1. Define product mood.
2. Define user’s main job.
3. Define information architecture.
4. Define visual hierarchy.
5. Define design system.
6. Define components and states.
7. Define responsive behavior.
8. Define accessibility baseline.
9. Define empty/loading/error/success states.
10. Run visual QA.

## Evaluation Questions
- Is the user’s next step obvious?
- Does this feel like a serious product?
- Does it work on mobile?
- Does the design support the app’s purpose?
- Are states and errors handled?
- Is the UI calm, clear, and not cluttered?

# Framework: Design Benchmark Adaptation

## Framework ID
FW-DESIGN-BENCHMARK-001

## Main Idea
Study high-quality apps for patterns. Do not copy branding or content.

## Process
1. Identify 3–7 best-in-class references.
2. Extract patterns: navigation, cards, onboarding, empty states, data views, interactions.
3. Map which pattern fits the app.
4. Improve/adapt for the user’s unique product.
5. Avoid copying protected content, design, branding, or trade dress.
