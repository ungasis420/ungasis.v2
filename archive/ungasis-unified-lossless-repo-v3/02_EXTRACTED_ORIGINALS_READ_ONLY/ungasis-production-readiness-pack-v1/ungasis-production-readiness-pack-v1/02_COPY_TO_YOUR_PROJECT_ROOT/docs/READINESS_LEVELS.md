# Readiness Levels

## Purpose

This file helps you choose the right strictness.

## Level 1: Learning

Use when you are studying.

Required:

- simple notes
- fake data
- no real secrets
- no real users

Status: safe for learning.

## Level 2: Personal use

Use when only you use it.

Required:

- backup
- simple tests
- no secrets in files
- notes for changes

Status: safe for you if low risk.

## Level 3: Private testing

Use when trusted people test it.

Required:

- permission matrix
- support contact
- feedback form
- known gaps list
- rollback plan

Status: safe for small test if reviewed.

## Level 4: Public MVP

Use when strangers may use it.

Required:

- security review
- privacy review
- support plan
- logs
- issue process
- release checklist

Status: not beginner-only. Get help.

## Level 5: Production

Use when real users depend on it.

Required:

- full tests
- monitoring
- rollback
- incident response
- access control
- dependency review
- release approval

Status: needs technical review.

## Feynman explanation

Readiness level means choosing how careful you must be based on who uses the project and what could go wrong.

## Layman analogy

Practicing cooking at home is Level 1. Serving paying customers is Level 5.
