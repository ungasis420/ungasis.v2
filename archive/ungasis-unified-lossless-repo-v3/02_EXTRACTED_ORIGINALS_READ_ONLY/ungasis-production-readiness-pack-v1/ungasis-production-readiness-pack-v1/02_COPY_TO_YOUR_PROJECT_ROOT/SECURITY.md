# Security Policy

## Simple security rule

Do not put secrets in project files.

Secrets include:

- passwords
- API keys
- tokens
- private certificates
- database connection strings
- client private data

## Reporting a security issue

If you find a security issue, write:

```text
Date:
What I found:
Where I found it:
Why it may be risky:
Who should review it:
```

## Risky actions need approval

A human must approve before the app or agent can:

- send messages
- delete data
- update records
- change permissions
- spend money
- publish public content

## Beginner analogy

Treat secrets like house keys. Do not leave them taped to the front door.
