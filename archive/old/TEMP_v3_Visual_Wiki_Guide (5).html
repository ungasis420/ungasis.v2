Pattern 1: The Sequential Pipeline

Agent A finishes → passes output to Agent B → Agent B finishes → passes to Agent C → final result.

Like a factory assembly line. Worker 1 cuts the wood. Passes it to Worker 2 who sands it. Passes it to Worker 3 who paints it. Each worker only does ONE job, then passes the product to the next person. The result is a finished, painted piece of furniture — none of them could have done all three jobs as well alone.

How it actually works: Each agent produces an OUTPUT (a file, a diff, a summary). That output becomes the INPUT for the next agent. Agent 1 writes a spec → Agent 2 reads that spec and writes code → Agent 3 reads that code and writes tests → Agent 4 reads everything and approves. The "passing" is just: the next agent reads what the previous agent produced.

Pattern 2: The Self-Healing Loop

Agent writes code → runs tests → if tests fail → reads error → fixes code → runs tests again → repeats until ALL tests pass.

Like a student taking a test with unlimited retries. They answer the questions, submit, get their score. If they failed any questions, they see WHICH ones they got wrong, study those specific topics, and retake the test. They keep retaking until they score 100%. The key: they learn from each failure.

    ┌─────────────────────────────────┐
    │         START: Get Task         │
    └──────────────┬──────────────────┘
                   ▼
    ┌─────────────────────────────────┐
    │     Agent Writes/Fixes Code     │
    └──────────────┬──────────────────┘
                   ▼
    ┌─────────────────────────────────┐
    │        Run Tests / Lint         │
    └──────────────┬──────────────────┘
                   ▼
              ┌─────────┐
              │ Tests    │──── YES ──→  ✅ DONE! Ship it.
              │ Pass?    │
              └────┬─────┘
                   │ NO
                   ▼
    ┌─────────────────────────────────┐
    │  Read Error Logs + Stack Trace  │
    │  Feed errors back to agent      │
    └──────────────┬──────────────────┘
                   │
                   ▼
              ┌─────────┐
              │ Retry    │──── NO ──→  ❌ Escalate to human
              │ Limit?   │
              └────┬─────┘
                   │ YES (retries left)
                   │
                   └──────→  ↑ Back to "Agent Writes/Fixes Code"

The magic ingredient is FEEDBACK. The agent doesn't just retry blindly — it reads the specific error message, understands WHAT went wrong, and makes a targeted fix. Like a GPS that says "wrong turn, recalculating" — it adjusts the route based on where you actually are, not just randomly trying new directions.

⭐ #1 Pick: Microsoft Conductor (YAML Pipelines)

This is literally built for what you're describing. You write a simple text file that says: "Agent 1 does X → if output contains 'error', go to Agent 2 → otherwise go to Agent 3." Zero tokens spent on routing — it's all in the YAML file.

Released May 14, 2026 by Microsoft. MIT license. Free. Works with Copilot SDK + Claude.

# Example: Sequential code pipeline with auto-fix loop
name: build-and-fix
entry: planner

agents:
  planner:
    prompt: "Break this feature request into implementation steps."
    model: copilot
    routing:
      - condition: "{{ exit_code == 0 }}"
        next: coder

  coder:
    prompt: "Implement the plan above. Write clean, tested code."
    model: copilot
    routing:
      - condition: "{{ exit_code == 0 }}"
        next: tester

  tester:
    prompt: "Run all tests. Report pass/fail with details."
    model: copilot
    routing:
      - condition: "{{ 'FAIL' in output }}"
        next: fixer          # ← Tests failed? Go to fixer!
      - condition: "{{ 'PASS' in output }}"
        next: reviewer       # ← Tests passed? Go to reviewer!

  fixer:
    prompt: "These tests failed: {{ previous_output }}. Fix the code."
    model: copilot
    routing:
      - condition: "{{ exit_code == 0 }}"
        next: tester          # ← Back to tester! (THE LOOP)
    max_retries: 5            # ← Stop after 5 attempts

  reviewer:
    prompt: "Review all changes for quality and security."
    model: copilot
    # No routing = end of pipeline

This YAML file is like a flowchart printed on paper. "If tests fail, go back to the fixer. If tests pass, go to the reviewer." The routing is decided by YOUR rules, not by the AI — so it's predictable and free (zero extra tokens for routing).

⭐ #2 Pick: Claude Code Hooks (Auto-Test After Every Edit)

Claude Code Hooks are shell commands that fire automatically when Claude edits a file. You can set up a PostToolUse hook that runs your tests every single time Claude changes code. If tests fail, the error is fed directly back to Claude — creating a natural self-healing loop.

// .claude/settings.json — Auto-test after every file edit
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "write:src/**/*",
        "hooks": [
          {
            "type": "command",
            "command": "npm test -- --bail --findRelatedTests"
          }
        ]
      }
    ]
  }
}

// What happens:
// 1. Claude edits a file
// 2. Hook auto-runs related tests
// 3. If tests fail → error output feeds back to Claude
// 4. Claude reads the error and fixes the code
// 5. Hook runs tests again
// 6. Repeat until tests pass!

Hooks are like a teacher standing behind the student. Every time the student writes an answer (Claude edits a file), the teacher immediately grades it (runs tests). If it's wrong, the teacher says exactly what's wrong (error message), and the student corrects it. This happens automatically — no one needs to tell the teacher to check.

How to Set This Up (Your Tools)

Three approaches from simplest to most powerful.

🟢 Level 1: Simplest — Claude Code Hooks (5 min setup)

You already have Cline + VS Code. Add a PostToolUse hook to auto-run tests. Cline naturally retries when tests fail.

// If using Claude Code (via Router with free models):
// Create .claude/settings.json:
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "write:src/**/*",
        "hooks": [
          {
            "type": "command",
            "command": "npm test -- --bail 2>&1 | head -50"
          }
        ]
      }
    ]
  }
}
// That's it! Self-healing loop is now active.

What you get: Every time the agent edits code → tests run automatically → if tests fail → error feeds back → agent fixes → tests run again → repeat until pass.

🟡 Level 2: Medium — Microsoft Conductor Pipeline (15 min setup)

Define your entire agent chain in one YAML file. Install Conductor, write the pipeline, run it.

# Install Conductor (Windows PowerShell):
irm https://raw.githubusercontent.com/microsoft/conductor/main/install.ps1 | iex

# Create your pipeline file: pipeline.yaml
name: feature-pipeline
entry: planner
agents:
  planner:
    prompt: |
      Break this feature into implementation steps.
      Feature: {{ user_input }}
    model: copilot
    routing:
      - next: coder

  coder:
    prompt: |
      Implement the following plan:
      {{ previous_output }}
    model: copilot
    routing:
      - next: tester

  tester:
    prompt: "Run: npm test. Report results."
    model: copilot
    tools:
      - shell
    routing:
      - condition: "{{ 'FAIL' in output }}"
        next: fixer
      - condition: "{{ 'PASS' in output or 'passing' in output }}"
        next: reviewer

  fixer:
    prompt: |
      Fix these test failures:
      {{ previous_output }}
    model: copilot
    routing:
      - next: tester
    max_iterations: 5

  reviewer:
    prompt: "Review all changes. Approve or request fixes."
    model: copilot

# Run:
conductor run pipeline.yaml --input "Add user profile page"

DIY Pipeline (No Extra Tools Needed)

You can do this TODAY with just your existing tools — manually chaining agents.

📋 The Manual Pipeline Method

You don't need any orchestrator to chain agents. You ARE the orchestrator. Here's how:

STEP 1: M365 Copilot (This Chat) — PLAN
You: "Break this feature into 4 tasks with acceptance criteria."
Copilot: outputs Task 1-4 with clear specs.
→ You COPY the output.

STEP 2: Cline (VS Code) — CODE
You: paste Task 1 spec → Cline writes code.
→ Cline auto-runs tests (if configured).
→ If tests fail → Cline reads errors → fixes → retries.
→ When tests pass → you COPY the diff summary.

STEP 3: ChatGPT Enterprise — REVIEW
You: paste the diff → "Review this code for bugs and security."
ChatGPT: outputs review with suggestions.
→ If issues found → back to Cline to fix.
→ If approved → proceed.

STEP 4: M365 Copilot — DOCUMENT
You: paste final changes → "Write changelog and docs."
Copilot: outputs documentation.
→ You commit everything. Done!

This is the "bucket brigade" approach. Like firefighters passing buckets of water hand-to-hand. Each person (agent) does their part and passes the result to the next. YOU are the person coordinating who passes to whom. It's manual but works perfectly and costs $0.
