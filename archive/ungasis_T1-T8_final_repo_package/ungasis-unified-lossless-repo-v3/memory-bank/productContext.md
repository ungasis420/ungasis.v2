# Product Context — Why UNGASIS Exists

## Why This Exists

Beginner solopreneurs can now build with AI assistants, but they often get lost because the AI forgets context, burns tokens, jumps between tools, and builds without a clear method. UNGASIS turns that chaos into a simple operating system.

## Simple Analogy

Prompt engineering is like writing one recipe. Context engineering is like stocking the whole kitchen: ingredients, tools, labels, notes, safety rules, and the meal plan are already prepared.

## Problems Solved

| Problem | What Happens Without UNGASIS | UNGASIS Fix |
|---|---|---|
| Context loss | Agent forgets project state | Memory Bank + CONTEXT.md |
| Token waste | Same info gets re-explained | 12-layer token efficiency system |
| Tool overwhelm | Too many AI tools and choices | Clear file hierarchy and tool routing |
| No methodology | Builds become random | Source → Blueprint → Modules → QA |
| Drift | Agents ignore old decisions | Persistent files and update rules |
| Wrong build | Agent builds before understanding | Planning, grilling, QA, and pass/fail checks |

## How It Should Work

1. User starts a session in Codespaces or another AI tool.
2. Agent reads `.clinerules/`, `AGENTS.md` or `CLAUDE.md`, and `memory-bank/`.
3. Agent understands current project state without asking the user to paste everything again.
4. Agent works one focused task at a time.
5. Agent writes durable output to files, not only chat.
6. Agent updates Memory Bank after major progress.
7. User can start a fresh session and continue cleanly.

## Product Promise

UNGASIS helps a beginner solopreneur turn AI from a forgetful chatbot into a structured project partner.
