Your Journey 🗺️
See the big picture before you start. Your goal is not to build a huge app. Your goal is to prove that one real person has a painful problem your small app can help.

The Simple Mental Model — Food Stall Analogy

Think of it this way: Open a small food stall before building a full restaurant. Prove demand first. Scale only after real customers come back.

Your Recommended Path (Hybrid Strategy)

No-code validation (Week 1) → AI-generated clickable prototype (Week 2) → GitHub-backed owned code if users care (Week 3) → Small public MVP + payment only if value is proven (Week 4+)

Why NOT go straight to code?

Code is expensive in time and attention, even when AI helps. A bad product with good code is still a bad product.

Why NOT stay forever in no-code?

Serious apps hit limits: user limits, workflow limits, monthly cost growth, vendor lock-in. You need ownership eventually.

🇵🇭 Philippines-Specific: Payments

⚠️ Stripe — NOT Available in PH

Stripe does not list Philippines as a supported country. Do not plan to use Stripe unless you have a company registered in a supported country.

✅ PayMongo — PH Local

PayMongo works for Philippines businesses. No setup or monthly fee. Supports GCash, Maya, credit cards, and bank transfers.

Best global option for digital products from PH: Lemon Squeezy — they are the Merchant of Record (they handle tax). Fee: 5% + $0.50 per transaction. Re-check payout details for Philippines before launch.

When Things Go Wrong — Failure Types

Key insight: Retrying a rate limit error works. Retrying a hallucination (wrong AI answer) makes it WORSE. Identify the failure type first.
#TypeHow OftenHow to Fix
1Transient — temporary error60%Retry with delay and random wait (backoff + jitter)
2Context Overflow — too much text15%Compress or summarize the conversation
3Hallucination — AI made it up12%Validate answer, use fallback model
4Cascading — one failure causes more8%Isolate the broken step, rollback
5Corruption — broken file or state5%Restore from last checkpoint

Token Smart ⚡
Tokens are how AI tools measure text. Every word, code line, and instruction costs tokens. This section teaches you how to spend tokens wisely.
Simple analogy: Tokens are like words in a text message. AI tools charge you by the word. More words = higher cost. Learn which words to cut.

Fill-% Zones — Monitor Your Context Window

The "context window" is how much the AI can remember in one conversation. When it fills up, the AI forgets old information. Watch these zones:

🟢 0–50%
🟡 50–70%
🟠 70–85%
🔴 85%+

🟢 Green (0–50%)

Full exploration mode. Read freely. Detailed answers. Examples OK.

🟡 Yellow (50–70%)

Efficiency mode. Shorter answers. Skip examples. Only read needed files.

🟠 Orange (70–85%)

Compaction needed now. Summarize history. Drop old context.

🔴 Red (85%+)

Emergency. No new files. Finish minimally. Save your work. Hand off.

MetricValue
1 message~3,000–5,000 tokens
15–20 messages~45,000–75,000 tokens (max per session)
Compact trigger60–70% full (not at 93% — too late!)
Context windows128K–200K tokens (varies by model)

Stay Safe 🔒
Safety is not optional. These rules protect your users, your business, and yourself. Read this section before you launch anything.
🚨 The Golden Rule — Memorize This:
Never paste API keys, tokens, passwords, private certificates, service-role keys, or connection strings into AI chats, public GitHub repos, screenshots, HTML files, or frontend code. Ever.
Never paste this into AI chats or GitHub: API_KEY=sk-... DATABASE_URL=postgresql://... STRIPE_SECRET=sk_live_... SUPABASE_SERVICE_ROLE=eyJ... Store secrets in .env files. Add .env to .gitignore. Never commit .env.
