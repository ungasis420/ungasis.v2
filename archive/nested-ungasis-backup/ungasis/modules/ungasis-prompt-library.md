## Data Level Quick Guide

| Level | Name | Use in prompts? | Beginner rule |
|---:|---|---|---|
| 0 | Public demo data | Yes | Safe fake data for examples, demos, screenshots. |
| 1 | Personal non-sensitive | Yes, with care | Notes, plans, non-sensitive project details. |
| 2 | Private personal | Only in trusted tools | Private notes, personal finances, private documents. Avoid random tools. |
| 3 | Company/internal | Approved work tenant only | Use only inside approved ChatGPT Enterprise or M365 workspace. |
| 4 | Secrets/regulated | Do **not paste values** | API keys, passwords, tokens, legal/medical/financial/PII. Use placeholders only. |

**Hard rule:** Never paste real API keys, passwords, service-role keys, access tokens, private certificates, production connection strings, or customer-sensitive data into a prompt. Use `[SECRET_NAME]`, `[DUMMY_VALUE]`, or `[REDACTED]`.


## How to Use This Library

1. Pick the category that matches the job.
2. Copy the prompt block.
3. Replace every `[PLACEHOLDER]`.
4. Run it in the suggested tool.
5. Check the quality checklist before acting.

**Tiny analogy:** A prompt is like an order slip in a restaurant. If the order says what dish, spice level, budget, and allergies, the kitchen can cook better. 🍳

**Beginner rule:** One prompt = one clear job. Do not ask one prompt to validate, design, code, deploy, monetize, and market all at once unless it is the project kickoff prompt.

### TPL-E2-001 — 📛 Idea brain dump & discovery

**🎯 Use when:** You have messy ideas and need AI to organize them before building.

**📋 Copy-paste prompt with placeholders:**

```text
Act as a startup product coach and beginner teacher.

Context:
- My name/context: Mel John Dimat, beginner Filipino solopreneur in Manila.
- Project: [PROJECT_NAME]
- Current lifecycle stage: [LIFECYCLE_STAGE]
- Target user: [TARGET_USER]
- Main problem: [PROBLEM_TO_SOLVE]
- Budget: $0 upfront where possible.
- Data level: [DATA_LEVEL_0_TO_4]
- Tools available: [TOOLS_AVAILABLE]


Task:
Turn my rough idea notes into 3-5 clear app or project ideas. Separate real user pain from nice-to-have features.

Output format:
1. Cleaned idea list
2. Target user for each idea
3. Pain/problem statement
4. Assumptions to test
5. Best first validation step
6. What not to build yet

Rules:
- Use simple English. Define jargon.
- Use tables or checklists when useful.
- Label assumptions as [ASSUMPTION: ...].
- Ask only blocking questions.
- Do not invent sources, prices, laws, or feature availability.
- If current facts matter, tell me exactly what to verify from official sources.
- Do not ask for real secrets. Use placeholders like [API_KEY_NAME] only.
Extra rules:
- Do not recommend coding yet unless the idea is already validated.
```

**✏️ Inputs:** [PROJECT_NAME], [LIFECYCLE_STAGE], [TARGET_USER], [PROBLEM_TO_SOLVE], [DATA_LEVEL_0_TO_4], [TOOLS_AVAILABLE], [ROUGH_IDEA_NOTES]

**📤 Expected output:** A short ranked list of project ideas with next validation action.

**✅ Quality check:** Each idea has a user, pain, value, risk, and next action.

**💡 Beginner note:** Dump everything first. AI will clean the mess.

**🔗 Best tool:** ChatGPT Enterprise Project

**🔒 Max data level:** 1

## Prompt QA Checklist

Before you run any prompt, check:

- [ ] Did I replace every `[PLACEHOLDER]`?
- [ ] Did I remove real secrets, tokens, passwords, and private customer data?
- [ ] Did I state my lifecycle stage?
- [ ] Did I ask for one clear output format?
- [ ] Did I include the data level?
- [ ] Did I ask for assumptions and safety checks?
- [ ] If current facts matter, did I require official sources?
- [ ] If the prompt may affect people, money, records, or permissions, did I require human approval?

## Common Beginner Mistakes

| Mistake | Why it hurts | Better move |
|---|---|---|
| Asking one giant prompt to do everything | AI mixes planning, building, and launching | Split into validation → plan → build → check |
| No data level | AI may suggest unsafe tools | State Level 0-4 every time |
| No output format | Output becomes messy | Ask for table/checklist/steps |
| No examples | AI guesses your style | Add one tiny example |
| Too much real data | Privacy risk | Use dummy data or summaries |
| No quality check | Weak output looks complete | Ask for acceptance criteria |
| Skipping source verification | AI may hallucinate current facts | Use the Source Verification prompt |
| Letting AI edit too much code | More bugs, harder rollback | Ask for smallest safe change |
