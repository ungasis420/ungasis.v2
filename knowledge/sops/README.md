# SOP Library — Standard Operating Procedures

Checklists are like flight plans. They prevent silly errors and keep workflows fast, even when you are tired or switching devices.

## What is an SOP?
An SOP is a step-by-step checklist. It outlines exactly how to do a recurring task without having to rethink it every time.

## SOP Template Format
Every SOP file must follow this structure:

```markdown
# [SOP Title]

## Trigger
What starts this procedure? (e.g., "Starting work in the morning", "A build error occurred")

## Steps
1. Step 1 description
2. Step 2 description
3. Step 3 description

## Time to Complete
Estimated minutes (e.g., 5 mins, 2 hours).

## Expected Output
What files or state should exist at the end.

## Gotchas
Common mistakes or warnings.

---
Last reviewed: June 2026 | Review by: September 2026 | Owner: Mel
```

## Naming Convention
- Files must use kebab-case.
- Naming format: `NN-verb-noun.md` (e.g., `01-idea-to-quest.md`).
- For daily/agent/emergency SOPs, use descriptive names (e.g., `start-pc-session.md`).

## Category Folders
- `project-lifecycle/`: Stages of project creation, deployment, and launching.
- `daily-workflows/`: Daily checks, device handoffs, and review routines.
- `agent-workflows/`: Rules for collaborating with AI agents (Antigravity, Cline, Jules).
- `emergency/`: Disaster recovery protocols (e.g., expired keys, git conflicts).
