# 00-revenue-validation.md — Pre-Quest Revenue Validation

## Trigger
A new project idea is proposed and needs screening before any folder creation or coding starts.

## Steps

1. **Evaluate the 5-Question Validation Framework:**
   Fill out the scorecard. Award 1 point for every "Yes".

| Number | Question | Validation Check | Score |
|---|---|---|---|
| 1 | Who has the problem? | User persona is clearly identified and reachable. | [ ] Yes (1 pt) |
| 2 | Who is the competition? | Competitors exist, proving the market is real. | [ ] Yes (1 pt) |
| 3 | Is there willingness to pay? | Similar products charge fees, or target users express intent to pay. | [ ] Yes (1 pt) |
| 4 | Can we build the MVP in <20 hours? | Core feature can be scaffolded using DNA. | [ ] Yes (1 pt) |
| 5 | Can we reach 100 users in 30 days? | Concrete distribution channels (Reddit, Discord) exist. | [ ] Yes (1 pt) |

2. **Calculate Scoring Rubric:**
   - **4/5 or 5/5:** PASS. Proceed to initialize the quest.
   - **3/5:** PIVOT. Use the Pivot Template below to refine the concept.
   - **<3/5:** KILL. Discard the idea and move to another concept.

3. **Check Kill Criteria:**
   - If the total market size is estimated to be less than 1,000 users, **KILL** the project immediately.
   - If the core MVP feature cannot be built in under 20 hours, **KILL** the project immediately.

4. **Pivot Template (If Score == 3/5):**
   If the idea is close but needs refinement, answer these questions:
   - *Target adjustment:* Can we narrow the target audience to a smaller, more desperate user group?
   - *Feature simplification:* What component can we cut to reduce build time under 20 hours?
   - *Monetization swap:* Can we switch from a subscription model to a simple one-time payment?

## Time to Complete
~30 minutes.

## Expected Output
A documented validation scorecard with a clear Go/No-Go status.

## Gotchas
- Do not let excitement bypass this step. If an idea fails the validation score, writing code is a waste of token resources and human time.
